05 · CLI 命令行参数

基础参数

# 启动交互式会话
claude

# 单次查询（Headless 模式）
claude -p "解释这个函数的作用"
claude --print "解释这个函数的作用"

# 指定模型
claude --model sonnet
claude --model claude-opus-4-6
claude --model opus[1m]   # 使用 1M token 上下文

# 指定输出格式
claude -p "查询" --output-format text        # 默认纯文本
claude -p "查询" --output-format json        # JSON 格式
claude -p "查询" --output-format stream-json # 流式 JSON

会话管理参数

# 继续最近一次会话
claude --continue
claude -c

# 恢复指定会话
claude --resume <session-id>
claude --resume   # 显示会话选择器

# 从文件加载初始提示
claude --init-prompt-file ./prompt.md

权限控制参数

# 指定权限模式
claude --permission-mode default        # 默认：询问确认
claude --permission-mode acceptEdits    # 自动接受文件编辑
claude --permission-mode plan           # 只规划，不执行
claude --permission-mode auto           # AI 分类器自动判断

# 危险模式：跳过所有权限检查（仅在沙箱环境使用！）
claude --dangerously-skip-permissions

# 指定允许/禁止的工具
claude --allowedTools "Read,Edit,Bash"
claude --disallowedTools "Bash"

管道与自动化

cat logs.txt | claude -p "解释这些错误"
git diff | claude -p "审查这些变更"
npm run build 2>&1 | claude -p "修复这个构建错误"
curl -s api.example.com/data | claude -p "为这个 JSON 生成 TypeScript 类型"

# 结合 jq 处理 JSON 输出
claude -p "列出所有函数" --output-format json | jq '.functions[]'

06 · 权限模式详解

五种权限模式

模式行为适用场景切换方式
🔵 Default 文件编辑和 Shell 命令前询问确认 日常开发，保持完整控制 Shift+Tab
🟢 AcceptEdits 自动接受文件编辑，Shell 命令仍需确认 信任代码修改，但不想随意执行命令 Shift+Tab 循环
🟡 Plan 只分析和规划，不执行任何实际操作 先看方案，再决定是否执行 Shift+Tab 循环
🟠 Auto AI 分类器自动评估风险，低风险自动执行 减少审批疲劳，熟悉用户适用 --permission-mode auto
🔴 BypassPermissions 跳过所有权限检查，完全自主执行 ⚠️ 仅在完全隔离的沙箱环境中使用！ --dangerously-skip-permissions

细粒度权限配置

在 .claude/settings.json 中配置：

{
  "permissions": {
    "allow": [
      "Read",
      "Edit",
      "Bash(git *)",
      "Bash(npm test)",
      "WebSearch"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(sudo *)",
      "Bash(curl * | bash)"
    ],
    "ask": [
      "Bash"
    ]
  }
}
规则优先级
deny > ask > allow

07 · CLAUDE.md 配置指南

文件位置与优先级

优先级（高→低）
├── ~/.claude/CLAUDE.md          全局个人配置（所有项目生效）
├── /project-root/CLAUDE.md      项目根目录配置
└── /project-root/src/CLAUDE.md  子目录配置（仅对该目录生效）

推荐 CLAUDE.md 模板

# 项目名称 - Claude Code 配置

## 项目概述
这是一个 [项目类型] 项目，使用 [技术栈]。

## 常用命令
- 启动开发服务器：`npm run dev`
- 运行测试：`npm test`
- 构建：`npm run build`
- 代码检查：`npm run lint`

## 代码规范
- 使用 TypeScript，严格模式
- 函数命名：camelCase
- 组件命名：PascalCase
- 注释语言：中文
- 缩进：2 空格

## 重要约束
- 不要修改 `src/legacy/` 目录下的文件
- 所有 API 调用必须经过 `src/services/api.ts`
- 新功能必须包含单元测试
💡 最佳实践
建议 CLAUDE.md 保持在 200 行以内，过长会降低 Claude 的遵循质量。

08 · 记忆系统使用指南

四层记忆架构

Layer 3: CLAUDE.md（人工注入，永久）
    ↑ 每次会话开始时加载
Layer 2: Auto Memory / MEMORY.md（自动积累，项目级）
    ↑ Agent 自动写入，跨会话持久化
Layer 1: Session Memory（自动提取，跨会话）
    ↑ 后台自动保存关键信息
Layer 0: Context Window（即时，单次会话）

Auto Memory 使用

Claude Code 会自动在 .claude/MEMORY.md 中记录：

  • 发现的 bug 和修复方法
  • 项目特定的命令和参数
  • 用户偏好和工作习惯
  • 架构决策和重要约定

MEMORY.md 的前 200 行（或 25KB）会在每次对话开始时自动加载。

# 查看记忆
/memory

# 手动触发记忆整合（Auto Dream）
请整合并优化你的项目记忆

上下文压缩触发时机

使用率触发动作用户感知
< 64%无操作正常
64%~75%MicroCompact（本地裁剪）无感知
75%~95%AutoCompact（生成摘要）可能看到压缩提示
> 95%Full Compact（紧急压缩）明显的压缩操作

09 · 会话管理

继续与恢复会话

# 继续最近一次会话（最常用）

# 显示会话选择器，选择要恢复的会话
claude --resume

# 恢复特定会话（通过 session ID）

会话回溯（Rewind）

在交互式会话中：

  1. 双击 Esc 打开回溯菜单
  2. 选择要回到的历史节点
  3. 从该节点继续，形成新的对话分支（Fork）

# 创建新的 worktree 用于并行开发
git worktree add ../feature-auth feature/auth
git worktree add ../feature-payment feature/payment

# 在不同终端中分别启动 Claude Code
cd ../feature-auth && claude
cd ../feature-payment && claude

11 · MCP 集成与扩展

MCP 配置方式

MCP（Model Context Protocol）服务器可通过两种方式配置：

方式一：settings.json 中配置

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/dir"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "your-token"
      }
    }
  }
}

方式二：项目级 .mcp.json 文件

{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "DATABASE_URL": "postgresql://localhost/mydb"
      }
    }
  }
}

常用 MCP 服务器

服务器功能安装
filesystem文件系统访问@modelcontextprotocol/server-filesystem
githubGitHub API 集成@modelcontextprotocol/server-github
postgresPostgreSQL 数据库@modelcontextprotocol/server-postgres
brave-searchBrave 搜索引擎@modelcontextprotocol/server-brave-search
puppeteer浏览器自动化@modelcontextprotocol/server-puppeteer

13 · Hooks 自动化配置

Hooks 类型

Hook 类型触发时机用途
PreToolUse工具调用前验证、日志、阻止危险操作
PostToolUse工具调用后格式化、测试、通知
NotificationClaude 发送通知时自定义通知处理
StopClaude 完成任务时清理、报告、后处理

Hooks 配置示例

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "echo '执行命令：' $CLAUDE_TOOL_INPUT | tee -a ~/.claude/audit.log"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [
          {
            "type": "command",
            "command": "npm run lint --fix $CLAUDE_FILE_PATH"
          }
        ]
      }
    ]
  }
}

14 · 多 Agent 与并行工作流

子 Agent 调用

Claude Code 可以启动子 Agent 并行处理任务：

> 请并行完成以下三个任务：
  1. 为 UserService 编写单元测试
  2. 为 AuthService 编写单元测试
  3. 为 PaymentService 编写单元测试

Coordinator 模式

启用 enable_coordinator_mode Feature Flag 后，Claude Code 可作为多 Agent 系统的总协调者：

  • 分解复杂任务为子任务
  • 分配给专门的子 Agent
  • 汇总结果并处理冲突
  • 维护全局状态一致性

并行工作流最佳实践

# 使用 Git Worktree 实现真正的并行
git worktree add ../task-a main

git worktree add ../task-c main

# 在三个终端分别运行
cd ../task-a && claude -p "实现用户认证模块" --dangerously-skip-permissions
cd ../task-b && claude -p "实现支付模块" --dangerously-skip-permissions

15 · CI/CD 与自动化集成

GitHub Actions 集成

name: Claude Code Review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
      - name: Install Claude Code
        run: npm install -g @anthropic-ai/claude-code
      - name: Run Code Review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          git diff origin/main...HEAD | claude -p "审查这些代码变更，重点关注安全问题和性能问题" \
            --output-format json \
            --allowedTools "Read" \
            --dangerously-skip-permissions

自动化脚本示例

#!/bin/bash
# 自动修复 lint 错误
npm run lint 2>&1 | claude -p "修复所有 lint 错误" \
  --allowedTools "Read,Edit" \
  --dangerously-skip-permissions \
  --max-turns 10

# 自动生成 changelog
git log --oneline v1.0.0..HEAD | claude -p "根据这些 commit 生成 CHANGELOG.md" \
  --allowedTools "Read,Write" \
  --dangerously-skip-permissions

核心文件详解

CLAUDE.md
~/.claude/CLAUDE.md  |  /project-root/CLAUDE.md  |  /project-root/src/CLAUDE.md
项目指令文件 — 每次会话开始时自动注入到系统提示中，是 Claude Code 最重要的配置文件。
  • 支持多级层叠：全局 → 项目根目录 → 子目录，优先级从低到高
  • 建议保持在 200 行以内，过长会降低 Claude 的遵循质量
  • 适合写入：项目概述、常用命令、代码规范、架构说明、禁止操作
  • 项目级 CLAUDE.md 建议提交到 git，方便团队共享
自动加载 多级层叠 建议提交 git 200行限制
MEMORY.md
~/.claude/MEMORY.md  |  /project-root/.claude/MEMORY.md
Auto Memory 索引文件 — 由 Claude Code 自动维护的记忆文件，跨会话持久化项目知识。
  • 前 200 行（或 25KB）会在每次对话开始时自动加载
  • Claude 自动写入：发现的 bug、修复方法、项目约定、用户偏好
  • 可通过 /memory 命令查看和手动编辑
  • Auto Dream 功能会定期整合和优化 MEMORY.md 的结构
  • ⚠️ 不建议手动大幅修改，可能破坏 Claude 的记忆索引
自动维护 前200行加载 跨会话持久化 可选提交 git
settings.json
~/.claude/settings.json  |  /project-root/.claude/settings.json
核心配置文件 — Claude Code 的主要配置文件，控制权限、模型、MCP 服务器等所有核心行为。
  • 全局配置（~/.claude/settings.json）：对所有项目生效
  • 项目共享配置（.claude/settings.json）：团队共享，建议提交 git
  • 项目本地配置（.claude/settings.local.json）：个人专用，加入 .gitignore
  • 优先级：本地配置 > 项目共享配置 > 全局配置 > 企业托管配置
核心配置 三级层叠 项目级建议提交 git

settings.json 完整结构示例

{
  // 权限配置
  "permissions": {
    "allow": ["Read", "Edit", "Bash(git *)", "Bash(npm *)"],
    "deny": ["Bash(rm -rf *)", "Bash(sudo *)"],
    "ask": ["Bash"]
  },

  // 默认模型
  "model": "sonnet",

  // MCP 服务器配置
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "."]
    }
  },

  // Feature Flags
  "featureFlags": {
    "enable_auto_memory": true,
    "enable_auto_compact": true,
    "enable_hooks": true
  },

  // Hooks 配置
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [{ "type": "command", "command": "npm run lint --fix" }]
      }
    ]
  },

  // 环境变量（传递给工具）
  "env": {
    "NODE_ENV": "development"
  }
}
settings.local.json
/project-root/.claude/settings.local.json
个人本地配置文件 — 仅对当前用户生效，不应提交到 git。
  • 适合存放个人 API Key、个人偏好、本地路径等敏感或个性化配置
  • 会覆盖 settings.json 中的同名配置项
  • 务必将 .claude/settings.local.json 加入 .gitignore
个人专用 ⚠️ 加入 .gitignore 覆盖 settings.json
managed-settings.json
Linux: /etc/claude-code/managed-settings.json
macOS: /Library/Application Support/ClaudeCode/managed-settings.json
Windows: C:\Program Files\ClaudeCode\managed-settings.json
企业托管配置文件 — 由 IT 管理员部署的系统级配置，优先级最高，用户无法覆盖。
  • 适合企业统一管控：禁止特定工具、强制使用内部 API 端点、限制模型选择
  • 用户的所有配置文件都无法覆盖此文件中的设置
  • 需要系统管理员权限才能修改
企业专用 最高优先级 用户不可覆盖 需管理员权限
.mcp.json
/project-root/.mcp.json
项目级 MCP 配置文件 — 独立于 settings.json 的 MCP 服务器配置，专门用于项目级 MCP 集成。
  • 与 settings.json 中的 mcpServers 配置合并生效
  • 适合将 MCP 配置与其他项目配置分离管理
  • 建议提交到 git，方便团队共享 MCP 配置

MCP 专用 建议提交 git 与 settings.json 合并

系统状态文件 — Claude Code 的运行时状态存储，包含认证信息和缓存数据。
  • 存储 OAuth Token、API Key 缓存、用户账户信息
  • 存储 Claude Code 的运行时状态和偏好缓存
  • ⚠️ 绝对不要提交到 git，包含敏感认证信息

~/.claude/keybindings.json

commands/ 目录

commands/
~/.claude/commands/  |  /project-root/.claude/commands/
自定义 Slash 命令目录 — 存放自定义命令的 Markdown 文件，文件名即命令名。
  • 文件名（不含 .md 扩展名）即为命令名，如 review.md → /review
  • 文件内容为命令的提示词模板，支持 {{变量名}} 占位符

# React 18 最佳实践

## 核心原则
- 优先使用函数组件和 Hooks
- 避免不必要的 useEffect
- 使用 React.memo 优化渲染性能

## 状态管理
- 简单状态：useState
- 复杂状态：useReducer
- 全局状态：Zustand（不推荐 Redux）

## 性能优化
- useMemo 缓存计算结果
- useCallback 缓存函数引用
- React.lazy + Suspense 懒加载
