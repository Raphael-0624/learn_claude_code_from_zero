Git Worktree：并行执行的基础设施

Git Worktree 为每个 Agent 提供独立的工作目录，彻底解决多 Agent 并行修改文件的冲突问题。

# 为多 Agent 创建 Worktree
git worktree add worktrees/frontend -b feature/frontend
git worktree add worktrees/backend -b feature/backend
git worktree add worktrees/tests -b feature/tests

# 查看所有 Worktree
git worktree list
# /project                    abc1234 [main]
# /project/worktrees/frontend def5678 [feature/frontend]
# /project/worktrees/backend  ghi9012 [feature/backend]
# /project/worktrees/tests    jkl3456 [feature/tests]

# 完成后合并
git merge feature/frontend feature/backend feature/tests

Coordinator 模式

✂️

任务分解

将大任务分解为可并行的子任务，分析依赖关系，识别可并行的部分

📋

任务分配

将子任务分配给最合适的 Agent，考虑 Agent 的专业能力和当前负载

📊

进度监控

实时监控所有 Agent 的执行进度，处理失败和阻塞情况

🔗

结果合并

合并所有 Agent 的输出，解决冲突，生成最终的综合结果

最佳实践

何时使用多 Agent？

✅

适合多 Agent

任务可明确分解为独立子任务 · 子任务依赖关系少 · 总工作量 > 2小时 · 需要专业化分工

❌

不适合多 Agent

任务高度耦合无法并行 · 总工作量 < 30分钟 · 需要频繁人工决策 · API 配额受限

💡 成本提示：多 Agent 会消耗更多 API token（多个 Agent 同时运行），但对于大型任务（>2小时），总体上更经济，因为每个 Agent 的上下文更小，token 效率更高。
