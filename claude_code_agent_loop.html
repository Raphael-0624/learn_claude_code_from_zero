Agent Loop 核心循环

Agent Loop（内部代号 nO）遵循经典的 Think → Act → Observe → Decide 循环，实现了 ReAct（Reasoning + Acting）模式。

🧠
Think
分析当前状态
决定下一步行动
↓
⚡
Act
调用工具
bash/read/write/grep
↓
👁️
Observe
接收工具执行结果
更新上下文
↓
🎯
Decide
继续循环 or
完成任务 or 请求帮助
↑ 继续循环 ↑
典型任务的循环次数分布

Plan Mode：先规划，再执行

Plan Mode 是 2026 年 1 月引入的重要特性，让 Claude 在执行前先制定完整计划，避免无效尝试。

1

只读探索

读取相关文件，分析代码结构，识别依赖关系（不修改任何文件）

2

生成计划

列出所有需要修改的文件，描述每个修改的内容，估计工作量和风险

3

用户确认

展示完整计划，等待用户批准，用户可以修改或拒绝

4

执行计划

用户批准后，按计划逐步执行，支持中途暂停和调整

# 启用 Plan Mode
claude --plan "重构整个认证模块"

# Plan Mode 输出示例：

# 📋 迁移计划：Express → Fastify
#
# 分析结果：

# - 找到 5 个中间件文件

执行阶段详解

📥

阶段一：收集上下文

加载 CLAUDE.md 和 MEMORY.md，分析任务确定需要读取的文件，收集环境信息（git 状态、Node 版本等）

⚡

阶段二：采取行动

按计划执行工具调用，每次执行前检查权限，更新上下文，处理执行结果

✅

阶段三：验证结果

修改代码后自动运行测试，验证修复有效，如果测试失败自动回滚并重试

错误恢复机制

Claude Code 实现了自愈查询循环（Self-Healing Query Loop），能够自动从多种错误中恢复。

💥

ContextOverflowError

上下文使用率超过 90%

→ 触发 Full Compact 压缩
📊

TokenLimitError

单次请求超过 token 限制

→ 升级到 Opus 模型
🔧

ToolExecutionError

工具调用失败

→ 分析错误，调整参数重试
🌐

ModelError

API 错误或网络问题

→ 指数退避重试（1s/2s/4s/8s）
🔐

PermissionError

权限不足，操作被拒绝

→ 请求用户授权
⏰

TimeoutError

执行超时（>120秒）

→ 分解任务，逐步执行
错误类型分布与恢复成功率

自动检查点

# 查看可用检查点
claude --list-checkpoints

# 输出示例：
# ID          时间                触发原因              状态
# cp_001      2026-04-07 14:30   before_file_write     可用
# cp_002      2026-04-07 14:45   after_major_milestone 可用
# cp_003      2026-04-07 15:00   before_context_compact 可用

# 恢复到特定检查点

# 恢复到最近的检查点
claude --resume latest

并发与并行执行

⚡

并行工具调用

当多个工具调用相互独立时，Agent Loop 会并行执行它们，大幅减少总延迟

🔀

任务自动分解

对于大型任务，Claude 会自动分解为子任务，使用多个子 Agent 并行处理

# 并行读取多个文件（Claude 自动并行化）
claude "同时读取 src/auth.ts、src/user.ts、src/db.ts，分析它们的依赖关系"

# 内部：三个 read 调用并行执行
# [read("src/auth.ts"), read("src/user.ts"), read("src/db.ts")]
# 同时发出，同时等待结果

最佳实践

📝

清晰的任务描述

提供具体的文件路径、预期行为、约束条件，避免模糊的"修复 bug"

📋

复杂任务用 Plan Mode

对于涉及多个文件的重构，先用 --plan 生成计划，审查后再执行

🔢

合理设置 max-turns

简单任务设 5-10 轮，复杂任务设 30-50 轮，防止无限循环

✂️

分解大型任务

将大任务分解为独立的小任务，每个任务一个会话，保持上下文干净

💡 Tasks 功能：使用 claude /task create "任务名" 创建持久化任务，即使会话中断也能恢复。任务状态保存在 .claude/tasks/ 目录中。
