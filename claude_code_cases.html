案例一：接手遗留代码库

难度：⭐⭐ 初级
耗时：约 2 小时
传统方式：2 天
提速：8x

场景：新加入团队，需要快速理解一个 3 年历史的 Node.js 项目，原开发者已离职，文档几乎为零。

1

生成项目地图

> 请帮我理解这个项目，按以下顺序进行：

1. 先读取 package.json，了解技术栈和脚本
2. 读取项目根目录结构
3. 找到入口文件，追踪主要模块
4. 识别核心业务逻辑所在位置

不要修改任何文件，只读取和分析。
完成后生成一份 docs/project-map.md，包含：
- 技术栈总结
- 目录结构说明
- 核心模块列表（每个模块一句话说明）
- 数据流向图（用 Mermaid）
2

识别技术债务

> 基于你对项目的理解，请识别技术债务：

分析维度：
1. 代码质量问题（重复代码、过长函数、命名混乱）
2. 安全隐患（硬编码密钥、SQL 拼接、缺少输入验证）
3. 性能问题（N+1 查询、缺少缓存、同步阻塞）
4. 测试覆盖（哪些模块没有测试）
5. 依赖风险（过时的依赖、已知漏洞）

输出格式：按严重程度排序的问题列表
3

建立 CLAUDE.md

> 基于你对项目的分析，帮我生成一份 CLAUDE.md 文件：

包含：
1. 项目概述（2-3句话）
2. 技术栈
3. 常用命令
4. 重要约束（特别是那些有技术债务的模块，标注"暂时不要修改"）
5. 已知问题

保存到项目根目录的 CLAUDE.md
✅ 结果
  • 2 小时内生成了完整的项目文档
  • 识别出 23 个技术债务问题，按优先级排序
  • 建立了 CLAUDE.md，后续所有会话自动获得项目上下文

案例二：从零搭建全栈项目

难度：⭐⭐⭐ 中级
耗时：约 4 小时
传统方式：2 周
提速：21x

场景：从零搭建一个任务管理 SaaS 应用（Next.js + NestJS + PostgreSQL），包含多租户、认证、实时通知。

1

架构设计（先设计，不写代码）

> 我要搭建一个任务管理 SaaS 应用，请帮我设计技术架构：

需求：多租户、用户认证（邮箱+Google OAuth）、任务管理、实时通知、数据导出

技术偏好：Next.js 14 + NestJS + PostgreSQL

请输出：
1. 系统架构图（Mermaid）
2. 数据库 ER 图（Mermaid）
3. 目录结构
4. 技术选型说明

先只做设计，不写代码。
2

分阶段实现

> 架构设计已确认，现在开始实现。

第一阶段：项目脚手架
1. 初始化 monorepo（pnpm workspaces）
2. 创建 apps/web（Next.js 14）
3. 创建 apps/api（NestJS）
4. 创建 packages/shared（共享类型定义）
5. 配置 TypeScript、ESLint、Prettier
6. 配置 Docker Compose（PostgreSQL + Redis）

请按顺序执行，每步完成后告诉我。
3

使用 Git Worktree 并行开发前后端

git worktree add ../task-app-frontend main
git worktree add ../task-app-backend main

# 终端 1：前端
cd ../task-app-frontend && claude
> 专注实现前端部分，后端 API 已在 localhost:3001

# 终端 2：后端
cd ../task-app-backend && claude
> 专注实现后端 API，前端在 localhost:3000
✅ 结果
  • 4 小时内完成了可运行的 MVP
  • 包含用户认证、任务 CRUD、基础 UI
  • 代码质量高，有完整的类型定义和测试

案例三：大规模代码重构

难度：⭐⭐⭐⭐ 高级
耗时：约 6 小时
传统方式：2 周
提速：14x

场景：将 50 个 React class 组件迁移为函数组件，不能影响现有功能。

1

分析与规划

> 请分析 src/components/ 目录下所有 class 组件：

1. 列出所有 class 组件（文件路径）
2. 按复杂度分类：简单 / 中等 / 复杂
3. 识别迁移风险点
4. 制定迁移顺序（从简单到复杂）

输出：迁移计划表（CSV 格式）
列：文件路径, 复杂度, 风险点, 建议迁移顺序
2

建立迁移规范

> 在开始迁移前，请帮我建立迁移规范：

生命周期方法对应关系：
- componentDidMount → useEffect(fn, [])
- componentDidUpdate → useEffect(fn, [deps])
- componentWillUnmount → useEffect(() => { return cleanup }, [])

创建一个迁移示例（选择中等复杂度组件）
生成迁移 checklist（.claude/migration-checklist.md）
3

批量迁移

> 开始批量迁移简单组件（共 20 个）：

迁移规则：
- 遵循 .claude/migration-checklist.md 中的规范
- 每个组件迁移后立即运行对应测试
- 如果测试失败，回滚并标记为"需要人工处理"
- 迁移完成后更新 .claude/migration-progress.md

请并行处理，每次处理 5 个组件，完成后报告结果。
✅ 结果
  • 6 小时内完成 50 个组件迁移
  • 测试覆盖率从 67% 提升到 82%（迁移过程中补充了测试）
  • 零功能回归

案例五：安全漏洞审查与修复

难度：⭐⭐⭐ 中级
耗时：约 4 小时
传统方式：1 周
提速：10x
> 请对整个项目进行安全审查，重点关注 OWASP Top 10：

1. 注入攻击（SQL 注入、命令注入）
2. 身份认证问题（弱密码策略、会话管理）
3. 敏感数据暴露（日志中的密码、API Key 硬编码）
4. 访问控制缺陷（越权访问）
5. XSS（跨站脚本）

输出格式：
每个漏洞：漏洞类型 | 位置 | 风险等级 | 修复方案 | 优先级

典型漏洞修复示例

// ❌ 漏洞：SQL 注入
const users = await db.query(
  `SELECT * FROM users WHERE email = '${email}'`
);

// ✅ 修复：参数化查询
const users = await db.query(
  'SELECT * FROM users WHERE email = $1',
  [email]
);

// ❌ 漏洞：JWT 密钥硬编码
const token = jwt.sign(payload, 'my-secret-key');

// ✅ 修复：环境变量
const token = jwt.sign(payload, process.env.JWT_SECRET);
