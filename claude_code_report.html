🤝 多 Agent 编排
Subagent + Agent Teams 两种协作模式，支持顺序/并发/交接/群聊四种编排模式
🔹 Subagent（子 Agent）
→ 父 Agent 通过 AgentTool 内联创建
→ 独立 context window，隔离执行
→ 运行至完成后返回结果给父 Agent
→ 适用：并行子任务、隔离危险操作
🔸 Agent Teams（Agent 团队）
→ 预定义命名 Agent 组，共享目标
→ Lead Agent 协调工作分配
→ Teammate Agent 各自独立 context window
→ Agent 间可直接通信

💡 技术借鉴与设计启示
对企业级 Agent 产品设计的核心启示
✅ 值得借鉴的设计
① 工具分层权限模型
三层权限（自动/询问/阻断）是平衡效率与安全的最佳实践，避免 Agent 拥有无限权限
② 记忆系统分层设计
短期+中期+长期的分层设计，Auto Dream 式定期整合防止记忆退化。差旅 Agent 可设计「行程记忆」「用户偏好」「企业政策」三层
③ Hooks 确定性控制层
在 Agent 推理之外保留确定性控制层，无论 AI 怎么推理，某些安全检查必须执行
④ 上下文分级压缩
不要等到 context 满了才处理，MicroCompact→AutoCompact→Full Compact 分级策略是长会话 Agent 必备设计
⑤ 双 Agent 分离模式
将「分析规划」和「执行变更」分离到不同 Agent，降低误操作风险。差旅 Agent 可设计「需求理解 Agent」和「预订执行 Agent」
⚠️ 值得警惕的设计问题
① 透明度问题
Undercover Mode 隐藏 AI 身份的做法引发强烈批评。更好的做法：明确披露 AI 参与
② 供应商锁定
强绑定 Anthropic API 导致 OpenCode 等项目被封锁。更好的做法：Provider 无关化设计
③ 权限过度
BashTool 可执行任意命令风险极高。更好的做法：最小权限原则，严格沙箱
④ 记忆隐私
记忆文件明文存储存在隐私风险。更好的做法：加密存储 + 访问控制
⑤ 发布安全
Source map 意外打包导致源码泄漏。更好的做法：CI/CD 流程中强制检查打包内容
